## 一、接入范围（5 个必选组件）

| # | 组件 | 来源 | 安装方式 |

| 1 | openspec CLI | npm 官方包 | `npm install -g @fission-ai/openspec@1.8.0`（版本锚定） |

## 二、手动安装

### openspec

```bash
npm install -g @fission-ai/openspec@1.8.0
# 官方源不可达时用镜像：
npm install -g @fission-ai/openspec@1.8.0 --registry=https://registry.npmmirror.com
```

**版本锚定：1.8.0**（[02-融合工作流](./02-融合工作流.md) 命令按此版本实测）。升级/降级需重新核对工作流命令。

### 自建技能组

```bash
npx skills@latest add Small-Sagittarius/spec-superpowers -g -y
```

交互式安装（自行挑选技能/agent）：`npx skills@latest add Small-Sagittarius/spec-superpowers`——**务必包含 `using-superpowers` 和 `writing-plans`**（工作流主流程技能）。

单技能：`npx skills@latest add Small-Sagittarius/spec-superpowers --skill=brainstorming`

### mattpocock

```bash
npx skills@latest add mattpocock/skills -g -y
```

> 自建技能组依赖 mattpocock 的 `grilling`（设计/计划双决策门），必须先装 mattpocock 或至少装 grilling：
> `npx skills@latest add mattpocock/skills --skill=grilling`

### android-pilot MCP

在 `~/.claude/settings.json` 的 `mcpServers` 加：

```json
"android-pilot": {
  "command": "npx",
  "args": ["-y", "android-pilot-mcp"]
}
```

### superpowers 规则块（CLAUDE.md 注入）

规则块为仓库根目录 `CLAUDE.md`（哨兵标记 `<!-- superpowers:begin -->` 与 `<!-- superpowers:end -->` 之间的内容）。手动注入：

1. 将哨兵标记之间的内容复制进目标 CLAUDE.md（保留 begin/end 标记）
2. 目标默认为全局 `~/.claude/CLAUDE.md`；项目级注入则写入项目根 `CLAUDE.md`
3. 目标已含 `<!-- superpowers:begin -->` 哨兵即视为已注入，跳过

## 三、更新

```bash
# 更新全部 skills（含自建 + mattpocock）
npx skills@latest update -g -y

# 更新单个
npx skills@latest update brainstorming
```

> 注意：`skills update` 需要网络访问 GitHub（clone 源仓库比对 hash）。本机 GitHub HTTPS 443 不稳定时可能失败，可改用 SSH 拉取（见常见问题）。

## 四、版本约定

| 对象 | 约定 |
|------|------|
| 自建技能 frontmatter `version` | 修改技能内容必须递增；当前 1.0.0（brainstorming 1.0.1） |
| 仓库 tag / Release | 整包版本记录；打 tag 时同步所有技能 version |
| openspec CLI | 锚定 `1.8.0`（[02-融合工作流](./02-融合工作流.md) 按此版本实测）；升级需重新核对命令 |
| 更新机制 | skills CLI 按 lock 文件 hash 增量更新（见下） |

**当前版本标记**：git tag `v1.0.0` + GitHub Release v1.0.0（https://github.com/Small-Sagittarius/spec-superpowers/releases）

### 升级检测机制

`skills` CLI 在 `~/.agents/.skill-lock.json`（全局安装清单）记录每个技能的安装状态：

```json
"brainstorming": {
  "source": "Small-Sagittarius/spec-superpowers",
  "sourceUrl": "https://github.com/Small-Sagittarius/spec-superpowers.git",
  "skillPath": "skills/brainstorming/SKILL.md",
  "skillFolderHash": "650a003..."   // 已装内容 hash，升级检测的核心
}
```

**检测命令**：

```bash
npx skills@latest update -g -y
```

- 拉取每个 source 的远程仓库 → 逐技能比对 `skillFolderHash` 与远程内容 hash
- 输出 `Found N update(s)`：N=0 全部最新；N>0 自动更新
- 注意：hash 是机器判定依据，frontmatter `version` 是给人看的语义版本，**两者都要维护**

### 技能发布流程（修改自建技能后）

1. 递增技能 frontmatter `version`（如 1.0.0 → 1.1.0）
2. `git commit` + `git push` 到 spec-superpowers 仓库
3. 打 tag：`git tag -a v1.1.0 -m "..."` + `git push origin v1.1.0`
4. 建 Release（gh 或网页）
5. 使用者执行 `npx skills update -g -y` 自动拉取新版

## 五、常见问题

| 问题 | 处理 |
|------|------|
| `skills update` 连不上 GitHub | 本机 github.com HTTPS 443 不稳定；确认网络后重试，或改用 SSH：`git config --global url.git@github.com:.insteadOf https://github.com/` |
| 技能装到 `.agents/skills` 但 claude 不生效 | Claude Code 读取 `.claude/skills/`；确认 `.claude/skills/<name>/SKILL.md` 存在 |
| `npx skills add` 报 PromptScript 错误 | 噪音，忽略——PromptScript agent 不支持全局安装，但 .agents/.claude 已正常落盘 |
| openspec 命令不存在 | 未安装或 PATH 未刷新；重开终端，或手动 `npm install -g @fission-ai/openspec@1.8.0` |
| gh 认证缺 read:org scope | 不影响接入（用 npx/npm，不依赖 gh）；仅影响 gh 命令行建仓，补 scope 或网页操作 |
